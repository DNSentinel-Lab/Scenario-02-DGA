# 🧾 Final Comparison — Ground Truth vs Defender Evidence

This comparison was created only after SOC and IR decisions were locked and the resolver had been returned to its safe state.

## 🧾 One event, different evidence views

| Perspective | What it knew / observed | Final interpretation |
|---|---|---|
| **Project Lead / Adversary — Musfira** | exact generator, hash, victim, namespace, private start/end | authorized controlled DGA execution completed successfully |
| **Resolver telemetry** | real query/reply events from `10.50.30.20`, generated-looking names, NXDOMAIN behavior | observable DNS facts only |
| **Detection v1.0** | five consecutive one-minute threshold matches | explainable DGA/high-NXDOMAIN detection condition met |
| **Isolation Forest** | all five corresponding live windows scored `ANOMALY` | behavior differed from learned normal baseline |
| **AI** | structured detection/DNS evidence | possible DGA/high-NXDOMAIN interpretation with evidence limits |
| **SOC — Sonia** | raw DNS, baseline, recurrence, ML, AI, client scope | **INCONCLUSIVE — escalation warranted** |
| **IR — Abdul-Rehman** | independently reproduced DNS evidence, context availability, response state | recurrent abnormal DGA-like/high-NXDOMAIN behavior confirmed; narrow containment justified after human approval |
| **Final reveal** | private operator timeline compared with defender evidence | defender stack observed the authorized official DGA run without operator knowledge during SOC/IR decisions |

## 👥 What matched across roles

### 📌 Operator vs resolver

The operator documented a five-minute generated-name run through the victim's normal DNS path. Resolver evidence independently showed a five-minute burst of rapidly changing qnames under the controlled namespace.

### 🚨 Resolver vs Detection v1.0

The raw behavior crossed the already-frozen rule in five consecutive one-minute windows.

### 🚨 Detection vs ML

Both the explainable rule and the Isolation Forest treated the same latest cluster as unusual, but for different reasons:

- Detection v1.0 used explicit volume/uniqueness/NXDOMAIN thresholds;
- ML measured distance from the learned baseline.

### 🤖 Automation vs human judgement

AI and ML strengthened triage context, but Sonia preserved the missing attribution evidence. This prevented the final SOC record from becoming “AI said DGA, therefore malware.”

### 🔎 SOC vs IR

IR reproduced the critical SOC numbers rather than merely trusting them. The two defender roles therefore reached compatible conclusions through separate validation steps.

## 🛡️ Response comparison

Selected observed qname:

```text
ywvuacnec7gmul193uc.dga-test.soclab.abdul4rehman215.tech
```

| State | Resolver result |
|---|---|
| Before containment | `NXDOMAIN` |
| Approved RPZ enforcement | `NOERROR` / `A 10.50.30.30` |
| After safe reset | `NXDOMAIN` |

Additional checks:

- sinkhole returned HTTP `200`;
- unrelated AWS DNS remained normal;
- Splunk showed the same qname change from `NXDOMAIN` to `NOERROR` during enforcement.

The response was therefore both **observable and reversible**.

---

## ✅ Final truth statement

The final reveal establishes that the unusual DNS behavior was intentionally generated by the authorized Scenario 02 operator in the controlled lab. That fact explains the exercise ground truth.

It does **not** invalidate Sonia's SOC conclusion. During the defender-only investigation, authorization and process identity were not available in the evidence. `INCONCLUSIVE — escalation warranted` was therefore a defensible SOC outcome at that point in the workflow.

Likewise, IR's containment decision was evaluated from the evidence and response objective available to IR, then executed only after explicit human approval.

---

## 🧬 What Scenario 02 proved

- a frozen explainable detection can surface fresh DGA/high-NXDOMAIN behavior;
- an unsupervised model can add a useful second opinion without becoming the verdict;
- AI can assist triage while remaining subordinate to raw evidence;
- SOC can preserve uncertainty without ignoring strong anomaly evidence;
- IR can independently validate a handoff rather than inherit its assumptions;
- Unbound RPZ can provide narrow, reversible DNS containment;
- a response is not complete until the redirect, destination service, unrelated DNS, SIEM evidence, and reset are all verified.
