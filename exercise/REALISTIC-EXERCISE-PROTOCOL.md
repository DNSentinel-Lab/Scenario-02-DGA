# 🧬 Realistic Exercise Protocol — Scenario 02

Scenario 02 was executed as a **realistic, information-separated adversary-emulation exercise**. The realism came from real DNS traffic, live defender telemetry, frozen controls, independent human decisions, and a real before/after DNS response.

## 📌 Role separation

### 👥 Project Lead / Adversary Operator

Musfira privately knew:

- the victim used for the controlled run;
- the generator path and hash;
- the exact execution command;
- the official UTC start/end;
- the controlled namespace;
- operator-side screenshots and notes.

During execution, the operator did not inspect Splunk, ML, AI, or the dashboard to decide whether the activity should be changed or repeated.

### 🔎 SOC Analyst

Sonia worked from defender-visible evidence:

- Detection v1.0;
- `dns_soc_dns` raw resolver events;
- Dashboard Studio;
- historical baseline/hunts;
- `dns_soc_ml` second-opinion results;
- `dns_soc_ai` summaries;
- defender asset/context information.

Sonia was not given the private operator command or exact operator ground truth before locking the SOC disposition.

### 🛡️ Incident Response

Abdul-Rehman began from Sonia's formal handoff and defender evidence. IR independently reproduced the critical DNS facts before deciding whether containment was justified.

The prepared RPZ/sinkhole path was **not** a pre-approved automatic action. Enforcement required explicit human approval.

## 🚨 Frozen-control rule

Before the official run:

- Detection v1.0 was frozen;
- ML was not retrained for the official run;
- the AI evidence contract was already built;
- RPZ remained safe/non-enforcing.

The operator did not tune activity to the detection threshold. A detection miss would have been a valid exercise result.

## 🎭 Ground-truth reveal gate

Private operator ground truth remained separated until defender decisions were locked:

```text
SOC disposition
→ SOC → IR handoff
→ IR classification
→ response decision
→ human approval
→ containment verification
→ RPZ reset
→ final IR conclusion
→ reveal / comparison
```

Only after this chain was complete was the official generator timeline compared with defender telemetry.

## 🧾 Evidence language

Public documentation distinguishes clearly between:

### 📌 Observed

- real resolver-visible DNS behavior;
- exact qnames/response codes/timing;
- Detection v1.0 matches;
- ML/AI outputs;
- SOC/IR decisions;
- RPZ redirect and reset.

### 🧾 Not proven by defender DNS evidence

- malware identity;
- endpoint compromise;
- initiating process;
- user identity;
- malicious intent;

### 🎭 Known only after reveal

- the DGA behavior was intentionally generated by the authorized Scenario 02 operator using the pre-deployed Python generator.

## 💡 Why this protocol matters

The final comparison is useful because each role reached its conclusion with the evidence appropriate to that role. The exercise therefore measures more than whether a search returned a row: it measures detection coverage, analyst reasoning, automation discipline, response judgement, technical verification, and evidence integrity.
